# ASTRAL BLOOM — 新作ゲームパック・コンセプト

## 作品の位置付け

**『ASTRAL BLOOM（アストラル・ブルーム）』** は、星屑と結晶植物が咲く軌道庭園を舞台にした、縦スクロール弾幕シューティングの新作パックである。基盤検証用の無機質なデモから離れ、**「美しい弾幕を見切って、危険な花園を浄化する」**という一貫した体験を第1ステージで提示する。

> 舞台は、壊れた気象制御衛星群が結晶植物へ変質した「硝子雨の庭園」。軌道保安機〈カデンツァ7〉は、暴走する庭園制御核を停止させるため、降り注ぐ花弁弾の中へ進入する。

| 項目 | 決定内容 |
| --- | --- |
| 表記タイトル | ASTRAL BLOOM |
| 日本語副題 | 星環のカデンツァ |
| ジャンル | 1人用・縦スクロール弾幕シューティング |
| 想定プレイフィール | 弾幕の形を見て安全地帯を探す、視認性重視の中難度 |
| 第1ステージ | 硝子雨の庭園（Glassrain Garden） |
| 自機 | 軌道保安機〈カデンツァ7〉 |

| UI方針 | 暗い宇宙背景に高コントラストの白・青緑表示。敵弾と自弾の色相を明確に分離する。 |

## 第1ステージの進行

第1ステージは、初回プレイで約3分を想定する。最初の40秒は基本移動とショットの確認、次の60秒は花弁を模した扇状・波状弾幕の見切り、最後のボス戦で円形・螺旋・狙い撃ちを組み合わせる。各セクションの開始時に短い警告または詩的なメッセージを出し、世界観と戦闘の変化を同期させる。

| 区間 | 秒数目安 | 敵・弾幕の役割 | プレイヤーに学ばせること |
| --- | ---: | --- | --- |
| 導入 | 0–35秒 | 花粉ドローンの直進と緩い扇状弾 | 自機ショット、低速移動、基本回避 |
| 花弁回廊 | 35–85秒 | 花弁精霊の波状移動と円形弾 | 弾列の間を横切る判断 |
| 結晶温室 | 85–130秒 | 大型ガーデナーの狙い撃ちと螺旋弾 | 自機狙い弾の誘導と切り返し |
| ボス戦 | 130–190秒 | 庭園制御核〈フローラ・オルビス〉 | パターン認識、ボムの使いどころ |

## 敵役と弾幕のルール

敵と弾幕の名称、見た目、動きの役割を分け、後からアートを差し替えてもゲーム上の役割が崩れないようにする。敵弾は敵種ごとに色を変えすぎず、危険弾はマゼンタ～珊瑚色、自弾は青緑～白で統一する。

| 定義ID案 | 表示名 | 挙動 | 主な弾幕 | 得点の役割 |
| --- | --- | --- | --- | --- |
| `pollen_scout` | 花粉偵察機 | 上部から直進後に退場 | 5way扇状 | 基本撃破 |
| `petal_wisp` | 花弁精霊 | 横方向に蛇行 | 低速の円形弾 | 位置取り |
| `crystal_gardener` | 結晶ガーデナー | 画面上部に滞在 | 自機狙い3連・螺旋弾 | 中型敵処理 |
| `flora_orbis` | フローラ・オルビス | ボス用の複数フェーズ | 花冠円形・種子狙い・蔓螺旋 | ステージ達成 |

## UI文言と演出方針

第1ステージでは、タイトル画面・ステージ選択・ボス警告・クリア・失敗画面をASTRAL BLOOM用に置き換える。ゲームシステムの用語は既存の `SCORE`、`LIFE`、`BOMB`、`GRAZE` を踏襲し、世界観テキストだけを日本語中心に差し替える。

| 場面 | 表示文言案 |
| --- | --- |
| タイトル | `ASTRAL BLOOM` / `星環のカデンツァ` |
| ステージ開始 | `STAGE 01 — 硝子雨の庭園` |
| 中盤警告 | `結晶温室に異常反応。大型個体を確認。` |
| ボス警告 | `GARDEN CORE DETECTED` |
| ボス登場 | `フローラ・オルビス — 軌道庭園制御核` |
| クリア | `GARDEN PURIFIED` |
| 失敗 | `CADENZA SIGNAL LOST` |

## アセット置換の初期スコープ

今回の作品パック実装では、まず暫定図形描画と色指定でゲーム進行・視認性を完成させる。アート制作工程では、自機、敵、ボス、背景、ロゴ、弾の演出、BGM、SEをこのコンセプトへ合わせて追加する。実アセットを入れる際は `assets/README.md` の論理名と権利記録の規約に従う。

## 初期受入基準

第1ステージの初期版は、タイトル・ステージ選択にASTRAL BLOOMが表示され、4種の敵役がデータ定義から出現し、ボス〈フローラ・オルビス〉を撃破するとクリアとなる状態を合格とする。難易度、アート、音声、物語、複数ステージは、初期版の試遊結果を踏まえて次工程で拡張する。
