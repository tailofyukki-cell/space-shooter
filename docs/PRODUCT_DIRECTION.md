# 同人弾幕シューティング・プロダクト方針

## 1. 目的

本プロジェクトは、単なる1本のゲームではなく、**アート、BGM、SE、テキスト、敵・弾幕・ステージ定義を差し替えて複数の作品へ展開できる弾幕シューティング基盤**を作ることを目的とします。最初の題材として小規模な縦長画面の弾幕シューティングを完成させ、その後はデータとアセットを交換することで、異なる世界観・物語・難易度の同人ゲームへ再利用します。

販売向けの初期ターゲットは**Windows 10/11向けのダウンロード版**とします。ゲーム本体をWeb技術で実装し、後工程でデスクトップランタイムに包む構成を採用することで、Mac版、Steam版、ブラウザ体験版への展開余地も保ちます。Mac版の配布には別途Appleの署名・公証工程が必要になるため、最初の販売版ではWindows版を品質保証の対象とします。

## 2. 製品コンセプト

> 「ルールは一貫して覚えやすく、弾幕は読める速さで美しく、何度も上達したくなる。」

プレイヤーは自機を上下左右に操作し、メインショットと低速移動時の集中ショットを使い分けて敵を撃破します。敵弾に被弾するとミスとなり、残機が尽きるとコンティニューまたはゲームオーバーになります。敵弾にかすった際のグレイズ、コンボ、スペルカード型のボス攻撃、リプレイ可能なステージ構成を基盤仕様に含めます。

| 項目 | 初期製品版の決定 |
|---|---|
| ジャンル | 2D縦スクロール弾幕シューティング |
| 操作 | キーボード、対応ゲームパッド、将来のキーバインド変更 |
| 基準解像度 | 1280×720、プレイフィールド 540×720 |
| 表現 | 2D Canvas API、図形・スプライト・加算合成エフェクト |
| ステージ構成 | 1面のデモ版を基盤に、最終製品は複数ステージへ拡張 |
| 勝敗 | 残機、ボム、コンティニュー、スコア、クリア記録 |
| 保存 | 設定、ハイスコア、解放状態をローカル保存 |
| 音声 | BGMループ、効果音の多重再生、音量別設定 |
| 配布 | 初期はWindowsダウンロード版、将来はMac・Steam・体験版へ展開 |

## 3. 技術方針

既存の静的Web版を破棄せず、描画・入力・ゲームループの知見を引き継ぎます。ただし、単一の `main.js` にロジックを集約する構成から、**ゲームエンジン、ゲーム定義、作品固有アセットを分離する構成**へ移行します。これにより、敵と弾幕の追加がJavaScript本体の改修ではなく、主にJSONデータと素材ファイルの追加で済むようになります。

ゲーム本体は依存関係を最小化したES ModulesとCanvas APIで構築し、開発時には通常のブラウザで素早く試遊します。販売ビルドではElectron系のデスクトップラッパーによりウィンドウ表示、フルスクリーン、ローカル保存、配布用パッケージを提供する方針です。アセット読込・ゲームロジックはWeb版とデスクトップ版で共有します。

| 層 | 責務 | 差し替え対象 |
|---|---|---|
| Core | ループ、描画、入力、衝突、プール、保存 | 原則固定 |
| Gameplay | 自機、敵、ボス、弾、アイテム、スコア | 原則固定、拡張可能 |
| Definitions | キャラクター値、弾幕、出現、ステージ、会話 | 作品ごとに差し替え |
| Assets | 画像、BGM、SE、フォント、ローカライズ文 | 作品ごとに差し替え |
| Shell | ウィンドウ、フルスクリーン、配布設定 | 配布先ごとに調整 |

## 4. 初期実装の到達点（Engine Demo v0.1）

最初の実装段階では、販売用の全コンテンツを作り切るのではなく、製品化できることを証明する**Engine Demo v0.1**を完成させます。このデモは、タイトル、設定、ステージ選択、1つのプレイ可能なステージ、中ボスまたはボス、リザルト、セーブを備えます。自機、敵、弾幕、ステージ進行、音声イベントはすべて宣言的な定義ファイルから読み込みます。

| 機能 | Engine Demo v0.1 | 製品版で拡張 |
|---|---|---|
| 自機 | 1機、ショット、低速、ボム、被弾判定 | 複数機体、ショットタイプ |
| 敵 | 雑魚2種、ボス1体 | 敵・ボスの追加 |
| 弾幕 | 直線、扇、円、回転、狙い撃ち | 複合パターン、レーザー、使い魔 |
| ステージ | 1面、タイムライン出現 | 複数面、会話、分岐 |
| スコア | 撃破、グレイズ、コンボ | ランキング、リプレイ |
| アセット | 暫定のライセンス安全な図形・自作音 | 作品固有の正式素材 |
| 設定 | 音量、フルスクリーン、キー設定の土台 | 詳細な操作・表示設定 |

## 5. 販売準備の必須事項

販売可能な完成品にするには、ゲームの実装以外にも、配布物の品質と権利を整える必要があります。すべての画像、音楽、効果音、フォント、プラグインは、商用利用と再配布の可否を記録します。配布物には利用規約、クレジット、動作環境、問い合わせ先、バージョン表記を含めます。ストアごとの年齢区分、税務、販売者情報、返金規約は販売者本人が選択・確認する事項であり、公開直前にストアの最新規約と照合します。

## 6. 今回の設計上の非目標

初期基盤では、オンライン対戦、サーバー運用、課金機構、ユーザー生成コンテンツ、クラウドセーブは扱いません。これらを切り離すことで、オフラインで完結する軽量なダウンロード作品として品質を高め、制作とテストの反復を速くします。

## 7. 開発原則

弾幕は「避けられること」を優先し、視認性を妨げる背景やエフェクトを避けます。危険な当たり判定よりも見た目を小さくし、プレイヤーの被弾判定は明示的に可視化できるようにします。弾幕パターンの乱数はシード化できるようにし、テストおよび将来のリプレイ機能を妨げません。ゲームデータにはスキーマ検証を設け、不正な定義を起動時に検出します。

## 8. 次工程

次工程では、本方針を実現するために、ディレクトリ構成、定義ファイル形式、弾幕命令、入力・衝突・音声のインターフェース、セーブデータ形式を具体化した技術仕様を作成します。仕様を確定した後、既存MVPを新しいエンジン構造へ段階的に置換します。
