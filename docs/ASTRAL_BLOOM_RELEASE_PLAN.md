# ASTRAL BLOOM — 販売リリース到達計画

## 判定

ASTRAL BLOOMは現時点で、**再利用可能な横スクロール弾幕ゲーム基盤と、第1ステージの試遊プロトタイプ**である。Windows向け配布基盤、ゲームパック、設定保存、実アート、横スクロール描画、リリース用チェックリストは存在するが、購入者へ販売できる完成品としては未達である。

以後は「動くプロトタイプを増やす」ことではなく、販売リリースの必須ゲートを順に閉じることを完成基準とする。どれか一つでも未完了の状態で販売開始しない。

## リリースゲートと現状

| ゲート | 販売版の合格条件 | 現状 | 次の対応 |
| --- | --- | --- | --- |

| R1: コアゲーム | 自機、通常敵、ボス、弾幕、被弾、ボム、スコア、クリア、リトライが一貫して機能する。 | **プロトタイプとして達成**。 | 実機通し試遊と難易度調整を実施。 |
| R2: 商品ボリューム | 作品として十分なステージ数、ボス、難易度、導入・結末、想定プレイ時間を備える。 | **未達**。第1ステージのみ。 | 全体構成を確定し、第2・第3ステージと最終ボスを制作。 |
| R3: 音声 | BGM、ショット、敵弾、撃破、被弾、ボム、ボス移行の音声があり、音量設定と場面遷移に連動する。 | **未達**。論理名と再生フックのみ。 | 次工程でBGM2曲とSE7種を追加。 |
| R4: 操作・アクセシビリティ | キーボード・ゲームパッド・一時停止・フルスクリーン・音量・キー割当・フォーカス復帰を確認する。 | **一部達成**。入力・設定・ゲームパッド基盤あり。 | キー再割当UI、実機ゲームパッド試験、操作説明を追加。 |
| R5: ブランド・販売物 | 正式な商品名、ロゴ、アイコン、タイトル演出、説明文、スクリーンショット、マニュアル、変更履歴を用意する。 | **未達**。プロトタイプ表記と仮の製品名が残る。 | `package.json`、Electron名称、README、画面文言を正式商品名へ固定。 |

## 優先制作順

1. **R0を維持する。** 今回の境界クリッピングを基準に、画面外描画・UI重なり・解像度崩れを回帰テストへ追加する。
2. **R3を完了する。** 第1ステージのBGM、ボスBGM、主要SEを実装し、プレイの手触りを完成水準へ近づける。
3. **R2を設計して制作する。** 全3ステージを最小販売版の目標として、各ステージの敵・ボス・アート・曲・物語を定義する。
4. **R4とR1を実機試遊で閉じる。** キーボード・ゲームパッド・フルスクリーン・解像度・長時間起動・被弾・ボム・リトライをWindowsで検証する。
5. **R5〜R8をリリース候補で閉じる。** 商品名を固定し、権利台帳、インストーラー、ストア素材、配布ハッシュを作成する。

## 販売版として固定する前の禁止事項

販売候補版を作るまで、`manifest.id`、設定保存キー、正式商品名、アセットのライセンス記録、配布バージョンを安易に変更しない。ゲームパックの見た目だけを更新する場合も、対象アセットがR6の権利記録に追加されていることを確認する。

Electronの現在の製品名 `Danmaku Engine Demo` は基盤用の仮名であり、販売版には使用しない。R5開始時に `package.json`、Electronのウィンドウ名、アプリID、インストーラー名、README、ゲーム内表記を `ASTRAL BLOOM` の正式表記へ一括更新する。

## 次の完了目標

次のマイルストーンは、**「第1ステージの音付き縦切りデモ」ではなく「音付き横スクロール第1ステージ」**である。BGM・SEを実装し、境界表示、アート、操作、ステージ進行を通しで試遊できる状態を第1の販売品質ゲートとする。
